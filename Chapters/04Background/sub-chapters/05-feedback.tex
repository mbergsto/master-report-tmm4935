\section{Rating-Based User Feedback}
\label{sec:rating-based-user-feedback}
One direction explored in this work is the use of user feedback to
refine recommendations over time. This section presents the relevant
background on rating-based feedback.

Feedback from users can be captured explicitly through numerical ratings
\parencite[Chapter~3.1]{bobadilla2013recommender_systems_survey}. 
This feedback can be stored and used to refine recommendations in
later interactions, so that continued use lets the system match a
user's preferences more closely over time
\parencite[Chapter~1]{ricci2010recommender_systems_handbook}.

A practical problem with explicit ratings is that some items 
receive few ratings, making their average score unreliable. 
This is a form of the sparse data problem, which arises 
whenever an estimate must be drawn from only a handful of 
observations 
\parencite[Chapter~3.3]{murphy2012machine_learning_probabilistic_perspective}. 
Bayesian smoothing addresses this by pulling the estimated score 
towards a neutral prior when little data is available. 
The resulting estimate balances the prior assumption against 
the evidence in the observed ratings 
\parencite[Chapter~3.3]{murphy2012machine_learning_probabilistic_perspective}. 
As more data accumulates, the observed average comes to dominate 
the estimate, because the volume of observations now outweighs 
the prior 
\parencite[Chapter~3.3]{murphy2012machine_learning_probabilistic_perspective}.

The problem of not having a sufficient amount of ratings 
also relates to the cold start problem. 
The cold start problem arises when a system 
cannot yet recommend reliably because too few ratings have been 
gathered 
\parencite[Chapter~3.2]{bobadilla2013recommender_systems_survey}. 
A particular variant is the new community problem, which refers 
to the trouble a freshly launched system has in accumulating 
enough rating data to recommend well 
\parencite[Chapter~3.2]{bobadilla2013recommender_systems_survey}.
