\label{ch:methodology-and-system-overview}
This chapter presents the methodological framework and describes the design 
and development of MLguide, a web-based decision-support system for machine 
learning method selection. 
Section~\ref{sec:dsr} introduces Design Science Research as the overarching 
framework. 
Section~\ref{sec:system-overview} gives a high-level overview of MLguide 
and its main components. 
The following sections describe the design goals, the development process, 
and the evaluation approach.

\section{Design Science Research}
\label{sec:dsr}

This thesis uses Design Science Research (DSR) as its methodological framework, 
following \textcite{peffers2007design_science_research_methodology} and 
\textcite{hevner2004design_science_information_systems_research}. 
DSR is a well-established approach for developing and evaluating decision-support 
systems \parencite{arnott2012design_science_decision_support_systems_research}, 
and has been applied in recent work combining machine learning with user-facing 
decision support 
\parencite{landwehr2022design_knowledge_deep_learning, dellermann2018design_principles_hybrid_intelligence}. 
In DSR, knowledge is gained by building and evaluating an artifact, 
producing both a usable system and knowledge that can inform future work of a similar kind
\parencite{landwehr2022design_knowledge_deep_learning, hevner2004design_science_information_systems_research}. 
The DSR approach is therefore suited for this work, where the research questions are investigated 
through the design and evaluation of the artifact, MLguide.

The DSR process consists of six activities: problem identification, defining objectives, 
design and development, demonstration, evaluation, and communication 
\parencite{peffers2007design_science_research_methodology}. 
These activities are nominally sequential, but iteration is expected. 
After evaluation, the researcher may return to design and development to improve 
the artifact before proceeding \parencite{peffers2007design_science_research_methodology}. 
Figure~\ref{fig:dsr-methodology-overview} shows how these activities map to the structure 
of this thesis.

\section{System Overview}
\label{sec:system-overview}

MLguide is a web-based decision-support system designed to help users select 
machine learning methods for a given problem. 
The user starts by describing their problem with text input, and can provide 
filters to narrow the scope, such as ML area and task type. ML area refers to 
the machine learning paradigm concept introduced in 
Section~\ref{sec:machine-learning-paradigms-and-tasks}. The term ML area is 
used from here on, following the naming in the ML Ontology that MLguide builds 
on. Figure~\ref{fig:mlguide-overview} gives a high-level overview of MLguide 
and its main components.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{Figures/03-research-methodology-system-overview/mlguide-system-overview.pdf}
    \caption[MLguide system overview]{System overview of MLguide.}
    \label{fig:mlguide-overview}
\end{figure}

The system uses two knowledge sources. 
The first is a structured ML knowledge graph containing information about machine learning methods and tasks, 
including links between methods and the research articles they appear in, among other things. 
The second is a database of research articles from the literature. 
With the help of these knowledge sources, the recommendation engine produces three outputs: 
a ranked list of ML methods, a set of supporting articles, 
and a starter notebook, a Jupyter notebook file with code generated by MLguide as a starting point for implementation.

\section{Design Goals}
\label{sec:design-goals}

MLguide is a continuation of the work 
done in the pre-master project \parencite{bergsto2026mlselection}, 
which focused on collecting and analysing research literature 
on ML in product development and production. Each article in 
the dataset was categorised by ML area, product lifecycle phase,
and application area, and ML methods were extracted from the 
articles, as described in Section~\ref{sec:pre-master-findings}. 
Based on this, a roadmap was developed that filtered 
and ranked articles and methods according to the 
user's selected ML area, PLC phase, and application area. 
A simplified version of this 
roadmap is shown in Figure~\ref{fig:ml-roadmap-pre-master}.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{Figures/04-system-design-development/roadmap-pre-master.pdf}
    \caption[ML selection roadmap]{Simplified ML method selection roadmap from the pre-master project \parencite{bergsto2026mlselection}.}
    \label{fig:ml-roadmap-pre-master}
\end{figure}

The pre-master project identified several directions for 
further development of the literature-based roadmap, 
including ontology-based ML knowledge representation, support 
for translating recommendations into an ML implementation, and 
user feedback to improve recommendations over time 
\parencite{bergsto2026mlselection}. These correspond closely to 
the gaps identified in 
Section~\ref{sec:related-work-and-existing-tools}, in particular 
the need to combine structured method knowledge with 
literature-based evidence and to extend method selection into 
support for implementation. MLguide extends the original roadmap 
into a web-based decision-support system that addresses these 
directions. The main design goals are to recommend 
relevant ML methods based on a problem formulation, 
using both structured knowledge and research literature, and to 
provide a starting point for implementation through generated 
notebooks. User feedback to improve recommendations over time is 
a secondary feature of the system rather than a main goal.

The system is primarily aimed at engineers and students who are 
new to machine learning and need structured guidance in choosing 
a suitable method. A web-based interface is chosen to lower the 
threshold for use, making it easy for others to access and test 
the system without installation.

\section{Incremental and Iterative Development}
\label{sec:incremental-and-iterative-development}

Incremental and iterative development suits a system of this kind, 
where features can be built and deployed one at a time and refined through repeated evaluation. 
MLguide was developed incrementally over the course of the master's project. 
New features and components were built and deployed one at a time, each adding 
to the working system. This approach is consistent with incremental software 
development, where the system grows through a series of versions rather than 
being built all at once \parencite[33]{sommerville2011software_engineering}.

Figure~\ref{fig:incremental-development} illustrates this process. 
Planning, development, and self-evaluation are carried out as concurrent 
activities, producing successive versions of the system. 

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{Figures/04-system-design-development/incremental-development.pdf}
    \caption[Incremental development process]{Illustration of the incremental development process, based on
    \textcite[33]{sommerville2011software_engineering}.}
    \label{fig:incremental-development}
\end{figure}

The development approach is also iterative. After a version is evaluated, the findings 
inform a return to design and development before the next version is built, 
consistent with the DSR process described by 
\textcite{peffers2007design_science_research_methodology}. 
In this work, the iterations are driven by two forms of evaluation: ongoing 
self-evaluation, in which the system is tested on example cases to check 
that the output is reasonable, and two rounds of user testing.

\section{Evaluation}
\label{sec:evaluation}

User testing and example-based evaluation offer two complementary ways of 
evaluating a system like MLguide. User testing shows how the system is received 
in real use, but the problems and the way the system is used cannot be 
controlled. Example-based evaluation examines the output for a set of 
constructed problem cases, where the input is controlled, so the output can be 
examined more systematically. The two approaches have different strengths and 
therefore complement each other. Both were used to evaluate MLguide.

\subsection{User Testing}
\label{sec:user-testing}

Machine learning courses at universities provide a natural setting for user testing. 
They bring together the intended user group, students who are 
learning to apply machine learning but have limited prior experience, and give 
them realistic problems to work on. The course TMM4128 Machine Learning for 
Engineers at the Norwegian University of Science and Technology (NTNU) offers 
one such opportunity. In collaboration with the course, student groups used 
MLguide for two of their course projects. The two projects are summarised in 
Table~\ref{tab:user-testing}.

The two projects differ in scope and focus. The first project has a 
well-defined problem, detecting anomalies in time series data using 
unsupervised learning. The groups are asked to compare at least three 
ML methods.

The second project is more open-ended. The groups are asked to analyse 
applications of reinforcement learning across four product lifecycle phases, 
product design, manufacturing, product use, and recycling, and to implement 
a simulated RL environment and a sustainability agent.

The user testing provides feedback on the system through 
the students' project reports. MLguide also has a feedback form available on 
the home page, where users can rate their overall satisfaction, 
report any technical problems, and note what worked well and what should be improved.
All users of MLguide, including students during user testing, therefore have the opportunity 
to provide feedback through the form.
This gives MLguide two channels for user feedback when conducting user testing.

\subsection{Example-Based Evaluation}
\label{sec:example-based-evaluation}

Example-based evaluation is also a natural part of iterative development, since 
the same constructed examples can be run on each version to check that behaviour 
is correct as the system changes. A set of examples is submitted to the system, 
and the output is examined to check whether it is reasonable and relevant for 
the given problem.

For this work, each example was written as a problem description representing a 
typical use case for machine learning in product development and production, and 
the examples were chosen to cover different ML areas and task types. Each example 
was submitted to MLguide, and the output was examined, including the ranked 
methods, the supporting articles, and the generated notebook. Because the 
examples were both written and assessed as part of this work, this evaluation is 
a structured review of the system's behaviour rather than an independent test.
